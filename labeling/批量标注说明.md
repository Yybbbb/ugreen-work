# IPC 批量标注说明

面向 **SAM3 HTTP 服务 + `batch-annotate/annotate_ipc.py`** 的全流程：从 GPU 机环境、拉起服务，到对 IPC 训练图做 person / vehicle / 附属属性及 cat、dog、package 的批量标注。

---

## 流程一览

1. 在 **GPU 服务器**上配置 `sam3` conda 环境（仅首次）。
2. 启动若干 **SAM3 服务进程**（每进程一个端口，监听 `/health`、`/annotate`）。
3. 在 **任意能访问服务 IP 的机器**上运行 `annotate_ipc.py`，写出每张图一个 JSON。

当前 **`annotate_ipc.py` 只调用 `POST /annotate`**（每张图、每个 prompt 各一次请求）。若使用带 **`/annotate_batch`** 的 `server_batch.py`，单图多 prompt 会更快，但需改脚本才能用上；未改脚本前，**`server.py` 与 `server_batch.py` 在 `/annotate` 上行为一致**，均可配合现有标注脚本。

## 二、GPU 端：启动 SAM3 服务

服务目录：`sam3-agent/sam3-service/`。

### 方式 A：仓库自带 `manage.sh` + `server.py`（推荐与仓库一致）

在 **服务所在机器**上：

```bash
cd /data0/work/LuoWeiXing/sam3-agent/sam3-service   # 按实际路径修改
bash manage.sh          # 启动
bash manage.sh health   # 检查
bash manage.sh stop     # 停止（仅杀 server.py）
```

当前脚本逻辑概要：

- `GPUS=(1 2 3 4 5 6 7)`，每 GPU **`INSTANCES_PER_GPU=2`**，端口从 **`BASE_PORT=8020`** 连续递增 → **8020–8033 共 14 个实例**。
- 使用 **`conda run --no-capture-output -n sam3`**，日志写入 `logs/server_gpu{ID}_port{PORT}.log`。

`annotate_ipc.py` 默认 `DEFAULT_SERVERS` 为 `http://192.168.111.2:8020` … `8033`，与上述端口一致时需把 IP 改成你机器的实际地址或启动时用 `--servers`。

### 方式 B：手动批量启动 `server_batch.py`

`server_batch.py` 额外提供 **`POST /annotate_batch`**；对 **`/annotate`** 与 `server.py` 兼容，可替代多实例部署。

**务必加 `--no-capture-output`**，否则 `nohup` 重定向到文件时，日志可能长时间只有一行 `nohup: ignoring input`，看起来像「没启动」（实则在加载模型）。

示例（GPU 使用 **1–7**，端口 **8020–8033**，与 `manage.sh` 常见布局一致；可按显存改为每卡 1 个实例）：

```bash
cd ~/sam3-agent/sam3-service   # 按实际路径
mkdir -p logs

for port in $(seq 8020 8033); do
    gpu_id=$(( (port - 8020) % 7 + 1 ))
    nohup conda run --no-capture-output -n sam3 python -u server_batch.py \
        --gpu-id "$gpu_id" --port "$port" \
        > "./logs/sam3_batch_${port}.log" 2>&1 &
    echo "Started port $port GPU $gpu_id"
    sleep 3   # 错开加载，减轻显存与 IO 尖峰
done
```

查看是否已开始打印加载日志：

```bash
tail -f logs/sam3_batch_8020.log
```

停止全部 batch 服务：

```bash
pkill -f "server_batch.py"
sleep 2
pkill -9 -f "server_batch.py"
```

### 单进程调试（前台）

```bash
cd sam3-agent/sam3-service
conda run --no-capture-output -n sam3 python -u server_batch.py --gpu-id 1 --port 8020
# 或
conda run --no-capture-output -n sam3 python -u server.py --gpu-id 1 --port 8020
```

看到 **Uvicorn running** 后再用 `curl` 测 `/health`。

## 三、健康检查与常见问题

```bash
curl -s http://127.0.0.1:8020/health
```

- **`Connection refused`**：该端口无进程监听 → 服务未启动或已退出；看对应 log 末尾是否有 OOM、路径错误等。
- **刚启动不久**：每个进程要 **加载整份模型**，可能数分钟；多进程同时启动会更慢，可适当加大循环里的 `sleep`。
- **日志不刷新**：检查是否去掉 `conda run` 的 **`--no-capture-output`**。

API 说明见 [sam3-service/README.md](sam3-service/README.md)；`server_batch` 的批量接口见 `server_batch.py` 内 `/annotate_batch` 注释。

## 四、运行 `annotate_ipc.py`

在 **能访问服务 HTTP 地址** 的环境执行（无需 GPU、无需本机装 SAM3）。

```bash
cd /path/to/sam3-agent/batch-annotate
pip install requests pycocotools tqdm numpy   # 客户端依赖

python annotate_ipc.py --resume
```

### 常用参数

| 参数 | 说明 |
|------|------|
| `--servers` | 逗号分隔，如 `http://192.168.111.2:8020,http://192.168.111.2:8021,...`；默认脚本内为 `192.168.111.2:8020–8033` |
| `--image-dir` | 图片目录（默认见脚本内 `IMAGE_DIR`） |
| `--output-dir` | 输出 JSON 目录（默认见脚本内 `OUTPUT_DIR`） |
| `--timeout` | 单次 `/annotate` 超时（秒），超时则跳过该图 |
| `--resume` | 跳过输出目录里已有同名 `.json` 的图片 |
| `--iou-threshold` | 属性框与 person/vehicle 框的 IoU 匹配阈值（默认 0.3） |
| `--mask-containment-threshold` | 口罩 mask 落在 person mask 内的比例阈值（默认 0.8） |

### 输出目录

- 每张图：`{图片主名}.json`
- 结束：`summary.json`
- 若有超时跳过：`skipped_timeout.txt`

## 五、`annotate_ipc.py` 在做什么（简要）

1. **并发模型**：对每个 **通过 `/health` 的** 服务 URL 启一个 worker 线程；共享一个图片队列，**每个 worker 固定用一个服务**，避免同一进程被多图挤爆。
2. **单图请求**：对每张图按内置列表顺序调用 **`POST /annotate`**（图片 + `prompt` + `confidence_threshold`），约 **30 次/图**（person、mask、各类属性与颜色、vehicle、简单类别等）。
3. **后处理**：
   - person 的 **上衣颜色 / 性别 / 年龄段**：各属性检测结果与 person 框做 **IoU**，过阈值后取高分。
   - **是否戴口罩**：用 **mask 与 person 分割的包含率** 判定。
   - **车辆颜色**：与 vehicle 框做 IoU 匹配。
   - **cat / dog / package**：只保留检测框与分数。
4. **容错**：无可用服务则退出；单请求超时则整图记为跳过；`--resume` 支持断点续跑。
