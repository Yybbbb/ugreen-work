PART 1

面积百分位 vs. 模型性能（Precision 视角）

将验证集按图片面积 (kpx) 从低到高排序后分档。Precision（精确率）= 正确预测数 / 总预测数， 衡量「模型输出一个颜色预测时，有多大概率是对的」。 每种颜色至少需 5 次预测才计入 Top‑3 排名。

为什么用 Precision 而非 Recall？ 在摄像头部署场景中，每次模型输出一个颜色预测，下游系统会据此做出决策。 Precision 回答的是「这次预测可信吗？」，而 Recall 回答的是「有没有漏掉真实颜色？」。 对于业务来说，低 Precision 意味着大量错误预测，比低 Recall（漏报）的影响更直接。 不过，对于 black / white 等高频颜色，Precision 和 Recall 非常接近；对于 orange / purple 等低频颜色，两者差异可达 10–40 个百分点。

💡 实施建议

1. 默认使用平衡方案：当 crop 的 short < 96 px 且 area < 25 kpx 时， 跳过颜色属性预测（仅输出分割 mask），此时过滤约 10% 的最差图片。
2. 短边是最强的单一判据——它直接决定上采样倍数。短边 < 64px（2.6% 图片）时上采样 ≥ 4×，Precision 已低于 0.75。
3. 长边作为辅助参考：建议 long ≥ 160 px，但单独使用区分度不足——竖长人体 crop 的瓶颈在短边。
4. 过滤后，剩余 90% 图片维持正常属性预测通路，整体颜色 Precision 保持在 ~0.83。
5. 与 Recall 方案的差异：若用 Recall 作为判据，阈值可放宽 10–20%（因为 Recall 天然高于 Precision for 多数颜色）， 但 Precision 方案更保守、更安全——它直接控制「错误预测」的比例。

APPENDIX

指标说明与方法备注

Precision 计算方式：Precision = 正确预测数 / 总预测数。 对于每张图片，模型对上衣和下衣各输出一个颜色预测（来自 pred_upper.txt / pred_lower.txt）。 若预测颜色与 GT 颜色一致，计为正确。全局 Precision 为所有图片的正确预测数之和除以所有图片的预测数之和。 每种颜色单独计算时，分母为该颜色的总预测次数，而非 GT 次数（后者是 Recall）。

Precision vs Recall 关键差异：对于高频颜色（black 上衣 GT=1,576, Pred=1,651）， 两者接近（Rec=0.898, Prec=0.858）；对于模型过度预测的颜色（下衣 orange GT=12, Pred=20）， Precision (0.150) 远低于 Recall (0.250)；对于模型保守预测的颜色（上衣 purple GT=98, Pred=68）， Precision (0.603) 高于 Recall (0.418)。部署时应根据业务需求选择侧重指标。

模型输入配置：PP-LiteSeg STDC2 · 短边 resize 至 256px · 补边至正方形 · 6 通道输入（RGB + Pose Heatmap ×3）· 双头输出（分割 8 类 + 颜色 11 类 × 2）· iter_40000 · 从头训练。当 crop 短边 < 96px 时，上采样倍数 ≥ 2.7×，信息损失显著。
